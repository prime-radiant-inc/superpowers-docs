# Portfolio: which docs, for whom (full study)

Law lives in the hub. This flow is the full-study pass: it answers "what
docs does this project need?" and it fronts every genre flow that runs at
full study. v1 of this family kept docs TRUE; the genre flows write them
WELL; this pass decides WHICH docs FOR WHOM — the leg that claim
verification can never supply.

## The model (Diátaxis-grounded, journey-serving)

- **Readers** (real people in real moments, not demographics): `user`,
  `operator`, `contributor`, `adopter`. A project has the readers it
  actually has — a 300-line internal utility may have only contributors.
- **Moments:** evaluate → get started → accomplish a task → recover →
  understand → extend.
- Doc types are Diátaxis-informed (tutorial = first success, how-to =
  task, reference = lookup, explanation = concepts) but serve the
  journeys, not the taxonomy — a project gets the docs its journeys need,
  never four-of-each.

## Process

1. **Ground truth first.** Read the README, the index if one exists, the
   directory layout, and how the project is actually used (its enacting
   surfaces). Who performs what? (Hub: the performer rule.)
2. **Enumerate the real readers and their moments.** For each, name the
   moment and the job — what they can DO when the doc set has done its
   job. No named reader for a cell → that cell gets nothing.
3. **Map the existing docs into the matrix** (the index's Reader column is
   the record). Name, with evidence:
   - **Gaps** — a real reader-moment with no doc. Findings, not mandates.
   - **Excess** — a doc with no reader (debt, not coverage).
   - **Mis-addressed docs** — content whose performing reader is not its
     addressed reader (an "onboarding" doc whose commands only an
     operator runs). The fix routes through the owning genre flow.
4. **Propose the portfolio** sized to the project: what exists and stays,
   what's re-addressed, what's born (each with reader, moment, job), what
   is explicitly NOT written and why.
5. **Confirm with the human as one batch decision** — with the
   classification (evergreen/point-in-time), the cast and resolved voice
   where a genre flow follows. This is the full-study gate.
6. **Persist:** the index gains/updates Reader cells; confirmed
   won't-write decisions land in the `Decided gaps` comment below the
   fenced table (dated). Doc births route through new-docs.md and the
   genre flows; nothing is written from inside this pass.

## Bootstrap (no index at all)

Run audit.md Phase 0 (ground-truth map + group classification) and this
pass as one motion — one human gate covering classification + portfolio.
Then the genre flows execute the confirmed plan.

## Re-entry

The portfolio re-enters at the next full study (a later audit, a set
redesign, "are these still the right docs?"). The `Decided gaps` comment
is what keeps settled decisions settled — re-litigate only what the
human reopens or what the project's surfaces have changed.
