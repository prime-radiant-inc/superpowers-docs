# Brochure design standard (rendered HTML deck)

Law lives in the hub; the content pipeline lives in marketing.md. This is
the visual standard for `docs/brochure.html`, adapted from
microsoft/amplifier-bundle-stories `context/presentation-styles.md` and
`context/responsive-design.md` (MIT, repo @ 3657bf1). The guideline files
are normative, not their shipped example — the example deck predates its
own guidelines (fixed pixel sizes, no `clamp()`); we copy the artifact
*class* (single-file keynote-dark HTML deck) and follow the guidelines.

## Skeleton

One mode: a deck. Slides as full-viewport sections; nav dots; one small
inline script for ArrowLeft/ArrowRight/Space/PageUp/PageDown/Home/End,
touch swipe, and dot clicks; `prefers-reduced-motion` respected (no
transition when set). No page/one-pager mode — add it only when a real
reader needs it.

## Self-containment

- One file. Inline CSS in `<style>`, inline JS in `<script>`.
- System font stack only. Never inline webfonts or images.
- No external requests of any kind; the file opens from `file://`,
  attaches to an email, and presents.
- Size is advisory: stay lean. Reference decks land ~17–30 KB.

## Typography and layout

- Fluid type via `clamp()` for every font size and icon — never fixed
  pixel sizes. Headline ≈ `clamp(28px, 5vw, 56px)`; body ≈
  `clamp(15px, 2.2vw, 19px)`; cite/footer ≈ `clamp(11px, 1.6vw, 13px)`.
- CSS custom properties at `:root` for the palette and type scale; the
  render writes the resolved voice's **Look** knobs into them:
  `--accent` (default `#0A84FF`), density (`informative` = card/step
  grids; `sparse` = one idea per slide, more whitespace).
- Content max-width ~1100px, centered; generous padding
  (`clamp(20px, 5vw, 80px)`).
- Grids: `repeat(auto-fit, minmax(min(<col>px, 100%), 1fr))` so cards
  reflow instead of overflowing on small viewports.

## Color and accessibility (dark keynote)

- Background `#000`; text `#fff`; WCAG AA floors: body text contrast
  ≥ 7:1 (`rgba(255,255,255,0.85)` or brighter on black), secondary text
  ≥ 4.5:1 (`rgba(255,255,255,0.65)` minimum — never lower for content).
- Surface hierarchy for cards: background `rgba(255,255,255,0.06)`,
  border `rgba(255,255,255,0.12)`, hover `0.10`/`0.25`. Don't stack
  opacities below the floors.
- Accent used for emphasis and structure, never for body text.

## Act treatment

- Acts I–II (user) carry the base accent.
- **Act III (owner/operator) shifts to a warm accent** (default
  `#FF9F0A`) on its slides — the visual signpost for the register change
  the cast law requires. The close returns to base.

## The honesty move: citation footers

Every content slide carries a muted one-line footer citing the doc that
verifies it: `docs/<file>.md §<section> · verified @ <sha>`. The deck
inherits content from BROCHURE.md (marketing.md owns that pipeline); the
footer is how a viewer audits any slide in one glance. No slide without a
citation, including the hook.

## Sentinel (first line of the file)

`<!-- do not edit; generated by the superpowers-docs documentation skill
from docs/BROCHURE.md @ <sha> -->`

The wording is load-bearing: it contains both generated-file markers
docmaint's exclusion recognizes ("do not edit", "generated by"), so
`scan` skips the rendered file. `<sha>` is BROCHURE.md's stamp SHA — the
equality cursor the re-render check compares (hub: regeneration rule).

## Restraint

Show the demo, not the adjectives. Real commands and really-produced
output (hub: show real things). The voice's Banned list applies to slide
copy exactly as to prose; headlines are declarative sentences, not
imperative fragments (voice.md).
